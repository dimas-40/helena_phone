## 0. 새로 찾은 것 — 배포 구조가 "전체 공개"다

`dtslib-cloud-appstore/.github/workflows/deploy.yml`:

```yaml
- uses: JamesIves/github-pages-deploy-action@v4
  with:
    branch: gh-pages
    folder: .          # ← 레포 루트 전체를 그대로 공개 배포
```

**"이 파일만 공개" 스위치가 없다. 레포 = 공개가 기본값.** gitignore된 것만 빠진다.

| 경로 | 공개 상태 |
|---|---|
| `DEVLOG_20260921.md` / `WHITEPAPER.md` / `CLAUDE.md` | **200** |
| `mcp/mcp-registry/index.json` (개인경로 **40건**) | **200 · 23,776B** |
| `id_ed25519` | 404 ✅ (gitignore 등록, 커밋 이력 0회 — 위생 양호) |

→ `index.json` 40건은 **레지스트리 파일 하나의 문제가 아니다.** 디렉터리 리스팅은 막혀 있지만
경로를 알면 파일은 그대로 받아진다. **배포 정의(`folder: .`)를 바꿔야 닫힌다.**

## 2. 레포가 어떻게 바뀌나

### 지금: 카탈로그가 둘인데 서로 안 맞는다

```
apps.json                    22개  ← 랜딩페이지가 그리는 것
                               └ install.command 있는 것 = 3개뿐
mcp/mcp-registry/index.json  34개  ← 기계용 (MCP 실물)
```

**"34개 MCP"와 "22개 앱"이 같은 목록이 아니다.** 페이지가 어느 쪽을 말하는지 불분명한 게
구조 전환이 막힌 진짜 원인.

### 바뀐 후: MCP 3분류가 페이지 뼈대

| 부류 | 무게 | 배포 방식 | 근거 |
|---|---|---|---|
| ① 순수 로직 | 수십 KB | **코드 통일 → curl 한 줄** | `universal` **17** |
| ② 브라우저/모델 의존 | 중 | 컨테이너/의존성 분기 | `heavy_portable` **5** |
| ③ 컨테이너 확정 | 2~16 GB | **GHCR 주소 50자** | `container_verified` **7** |

- **배포처**: Vercel ✂(404 확인 완료) → GitHub Pages 단독
- **통제점**: private + PIN
- **페이지 성격**: "설치 안내" → **"주문서/트리거 목록"**

⚠️ 레지스트리 `workcenter:[laptop,minipc,phone]` **30개**는 낙관치 —
폰은 **배치 트리거만 실증**, 상주 실행은 미구현.
