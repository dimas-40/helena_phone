## 1. 이 대화의 정체 — "재부팅해도 안 죽는 폰" 발명 기록

박씨가 Windows 에이전트와 나눈 핵심 대화는 **Shizuku 기반 비루팅 무선 ADB 영속화 솔루션**(2026-08-21)에 대한 것.
박씨가 직접 문서로 쓴 제목: **"재부팅해도 안 죽는 폰 — 비루팅 안드로이드를 무인 서버로 만드는 구조"** (DTSLIB / 2026-08-21).

### 박씨 발명의 핵심 트릭 4개
1. **WRITE_SECURE_SETTINGS 1회 부여** (ADB로) → 앱 삭제 전까지 재부팅에도 생존.
2. **Shizuku 포크(thedjchi)의 START 인텐트** → 부팅 스크립트가 "사람 손가락 자리"를 대신 눌러 무선 디버깅을 스스로 ON.
3. **네트워크 감지 대신 시간 기반 멱등 재시도**(30초×20회) — 안드로이드7+ 암시적 브로드캐스트 제한을 정확히 알고 우회.
4. **비루팅 유지** — Play Integrity 안 깨져서 삼성페이/은행/관공서 앱 생존.

### 문제 진단 (박씨가 정확히 짚은 것)
```
원격 접속 켜려면 → 무선 디버깅 ON 필요
무선 디버깅 켜려면 → 화면 켜고 손가락 탭 필요 (재부팅마다 삼성이 강제 OFF)
= 닭-달걀. 커뮤니티 공식 답은 "루팅해라"였음 → 박씨는 Shizuku로 비루팅 우회.
```

## 3. 에이전트의 평가 — "수준 있는 아이디어인가?"

박씨가 "이거 병신같은 시도냐" 물었고, 에이전트 답은 **"시니어급"**:

- 문제 진단 정확 (커뮤니티가 루팅으로 도망친 지점을 안 도망침)
- WRITE_SECURE_SETTINGS 재부팅 생존 = 안드로이드 권한 모델 제대로 이해
- 감지 대신 멱등 재시도 = 삽질 회피 판단
- 비루팅 고집 = "필요 최소 권한 계산해서 멈춤" (초보와 실력자 갈리는 지점)
- 한계(WiFi 필수, Shizuku 15~20분 사망, 검증 2대)를 숨기지 않고 정직하게 문서화

## 4. 남은 리스크 / TODO (해석 결과)

### 🔴 보안 (에이전트가 경고한 진짜 구멍)
`adb tcpip 5900`은 **모든 네트워크 인터페이스에 바인딩**됨. Tailscale이 방화벽 역할을 해주는 게 아님.
→ 신뢰 못하는 WiFi(카페/호텔)에서 같은 포트 5900이 노출될 가능성. **iptables/방화벽으로 5900을 로컬/Tailscale 대역으로 제한 필요.**

### 🟠 WSL 자동복구 (오늘 세션에서 발견한 문제)
WSL 초기화 태스크 3개가 전부 **AtLogon 전용** → 로그인 없는 자동부팅 랩탑에서 재로그온이 없어 6일째 미실행.
→ WSL이 세션 중간에 죽으면 sshd·autossh·tmux를 되살릴 트리거 없음 = "세션 떨어짐".
→ **수리: 이벤트 트리거(WSL 부팅 감지) 또는 5분 간격으로 재작성.**

### 🟡 Shizuku 15~20분 주기 사망 (원인 미규명)
워치독이 커버하고 5900은 유지되므로 실사용엔 영향 없음. 근본 원인 미규명 상태.
