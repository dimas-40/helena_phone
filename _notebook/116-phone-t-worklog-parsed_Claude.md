## 0. 먼저 이름 정리 — 기억하신 것과 실물이 갈린다

"화면녹화 MCP = 폰티 = 컨테이너 만들려던 것"이라고 하셨는데, **실물은 셋으로 나뉘어 있다.**
한 덩어리로 기억하면 어긋난다.

| 이름 | 정체 | 어디 | MCP인가 | 컨테이너 |
|---|---|---|---|---|
| **Phone T** (`phonet`) | 화면녹화 raw → YouTube 규격 **편집 CLI** | **이 폰** (`scripts/yt_edit.py`) | **아니다** | 원본이 이쪽 |
| **`po-edit-cell`** | 위 편집기를 구운 **컨테이너** | GHCR (581MB) | 아니다 | ✅ 이미 있음 |
| **`mcp_phonerec`** | **녹화**를 시키는 MCP (`parksy-phonerec`, 툴 2개) | **미니PC** | **맞다** | 없음 |

- **Boss가 "MCP"라고 부르신 것 = `mcp_phonerec`**(진짜 MCP, 녹화 담당). 미니PC에 있고 **미완·실기기 미검증·미등록**.
- **Boss가 "폰티"라고 부르신 것 = Phone T**(이 폰, 편집 담당). **MCP가 아니다** — 그냥 CLI다. `~/.claude.json`에 등록된 적 없다(확인함).
- **"컨테이너 만들려던 것" = `po-edit-cell`**. 그런데 **이미 만들어져 있다**(581MB, 앱스토어 등록까지 됨). 만든 게 아니라 **안 맞춰진 게** 남았다.

> 즉 셋은 한 줄로 이어진다: `mcp_phonerec`(미니PC·녹화) → **Phone T**(폰·편집) → `po-edit-cell`(컨테이너·같은 편집기). **지금 끊긴 곳은 마지막 고리다.**

## 4. 이 작업에서 **두 번 갈아엎은 판단** (기록 가치 있음)

**① `avg_frame_rate` 처방이 그대로 버그를 만들었다.**
09-22 낮 devlog의 처방은 "`r_frame_rate`를 쓰라"였다. 그게 컷을 조용히 무시하게 만들었다.
삼성 화면녹화는 **VFR** — 선언 `60/1`, 실제 간격 `82.73fps`. 프레임 N을 N/60초 자리에 놓으면 **17.7초 빨라진다**.
→ 정정: **fps를 두 개로 나눈다.** 컷 이어붙일 **간격**은 `avg_frame_rate`, **출력 fps**는 선언값 + `fps=60` **필터**(타임스탬프 인지).
→ `-r 60`·`-fps_mode cfr` **출력 옵션으로는 못 고친다**(개수만 센다). `setpts=PTS-STARTPTS`도 안 된다(동기화는 맞지만 `select` 구멍을 안 메움).

**② "컨테이너와 차이는 베이스 이미지뿐"은 내 주장이지 실측이 아니다.**
README와 devlog에 그렇게 썼지만, **컨테이너에 같은 파일을 실제로 돌려 확인한 적이 없다.** 그대로 명시돼 있다(README §9, devlog 말미).

**③ 내가 낸 결함(기록됨):** "100.2초 성공"을 검증 통과로 적었다 → 실제로는 47.48+52.69 = **컷이 안 먹은 값**이었다.
