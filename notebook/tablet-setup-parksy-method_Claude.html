Boss 지시: 허브(dtslib-papyrus)에 어제·그제 저장된 “터닝 포인트 기점” 기준으로

0. 기점 (터닝 포인트 · 2026-08-17)

지금까지 : 아이디어 소설 — 설계·구상·스캐폴드·플랜 쓰기
오늘부터 : 실제 구현   — 보급형(S21)에서 되는/안 되는 직접 돌려보기
앞으로   : 피드백 루프 — 되는/안 되는 미러 → 재수정 → 재구현

판정 기준 전환: “말(설계)이 맞는가” → “구동이 되는가”.

1. 태블릿 정체 (4계정 4세계 중 태블릿 칸)

항목 값
Google 계정 Thomas.tj.Park@gmail.com
디바이스 태블릿
계층 Tier 2 · 확장형 (S21 보급형 < 태블릿 < S25 Ultra)
감각 노드 손(펜/터치/그림) — 손끝(말초 촉각)
세계 역할 확장형 워크센터 (방송 키트)
하는 일 그림·손글씨 OCR·드로잉 자산·화이트보드 방송
environment TBD (미정)
상태 ⏳ 신규 예정 (planned)
구축 순서 #2 — 누나폰(S21) 다음

2. 공장 토폴로지 — 태블릿은 “옵션”

공장(로케이션) 워크센터 방식
우리 공장 (PC+Claude) 2개 (S25 Ultra + WSL/저가 PC) 중앙 공급 · 임대 가능
태블릿 공장 옵션 필요시 우리 WSL 임대
누나폰 공장 (S21) 자체 (proot-Ubuntu 2) 독립 리걸 엔터티 · 자급 · 임대 불가

→ 태블릿은 자체 워크센터가 필수가 아니다. 우리 WSL을 빌려 쓸 수 있다.

3. 핵심 비대칭 (설계의 본질)

“태블릿이 스펙은 높아도 워크센터는 임대(의존), 누나폰이 스펙은 낮아도 자급(독립).”

스펙 서열과 인프라 자립도는 일치하지 않는다. 이 비대칭이 parksy 공법의 본질.

4. 감각 트라이앵글 (기기 정체성 = 감각 확장)

           시각 — 글래스 (1인칭 연속 녹화·GUI 대체)
              /                    \
             /                      \
말/음성+캡처+제어 ──────────── 펜/터치/그림
     폰 (S25 Ultra)              태블릿
  • 태블릿 = 손끝(펜/터치) → 그림·손글씨 OCR·드로잉 자산·화이트보드 방송.
  • 기기 정체성은 스펙(컴퓨트 축)이 아니라 감각(감각 축) 으로 정의.
  • 뇌는 S25(폰), 태블릿·글래스는 뇌에 붙는 컴패니언(IO).

5. 검증 원장 (28레포 × 멀티디바이스 = 2D 매트릭스)

  • 28레포 5-Tier = 생산 라인(순서), 멀티디바이스 = 공장(로케이션).
  • 각 칸 = “이 레포가 이 워크센터에서 실제로 구동되는가” 의 실측 기록.
  • 계획이 아니라 검증 원장. 중요한 건 레포 숫자가 아니라 검증된 칸의 수.
  • 한 공장에서 검증된 레포 패턴 = 다음 공장의 스캐폴드로 재사용.
  • 루프: ①미러(실측→뇌) → ②자식 → ③재수정(랩) → ④검증 → ⑤선물(완결만→워크센터) → ⑥기록.

6. 운용 원칙 (parksy 공법 §9)

  1. 2 디바이스 캡 — 병목은 돈이 아니라 주의력.
  2. 앵커 로테이션 — S25 Ultra = 항상 켜두는 앵커, 두 번째 슬롯은 S21 ↔ 태블릿 로테이션.
  3. 비용 — 주 $10 수준. 돈으론 거의 공짜, 주의력으론 비싸다.
  4. 성과 지표 — “한 주에 몇 개 레포/기기가 검증·양산됐나”.

7. ⚠️ 이 환경과의 갭 (Boss 확인 필요)

허브 SSOT의 태블릿 = Thomas.tj.Park 계정 / Tier 2 / 환경 TBD / 신규 예정.
반면 이 proot 환경의 실제 remote = dimas-40 (S21 또는 태블릿 미확정, 계정도 다름).

→ 네가 말한 “태블릿 전용 워크센터”로 가려면, 이 환경을 허브의 태블릿 칸(Thomas.tj.Park / Tier 2) 에 매핑할지,
아니면 dimas-40 = 새 태블릿 전용 계정으로 별도 설정할지 정해야 함.
(아직 이 환경이 “S21”인지 “태블릿”인지도 실측 필요 — 시스템상 S21로 잡힘)
