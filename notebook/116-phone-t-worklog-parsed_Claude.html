0. 먼저 이름 정리 — 기억하신 것과 실물이 갈린다

“화면녹화 MCP = 폰티 = 컨테이너 만들려던 것”이라고 하셨는데, 실물은 셋으로 나뉘어 있다.
한 덩어리로 기억하면 어긋난다.

이름 정체 어디 MCP인가 컨테이너
Phone T (phonet) 화면녹화 raw → YouTube 규격 편집 CLI 이 폰 (scripts/yt_edit.py) 아니다 원본이 이쪽
po-edit-cell 위 편집기를 구운 컨테이너 GHCR (581MB) 아니다 ✅ 이미 있음
mcp_phonerec 녹화를 시키는 MCP (parksy-phonerec, 툴 2개) 미니PC 맞다 없음
  • Boss가 “MCP”라고 부르신 것 = mcp_phonerec(진짜 MCP, 녹화 담당). 미니PC에 있고 미완·실기기 미검증·미등록.
  • Boss가 “폰티”라고 부르신 것 = Phone T(이 폰, 편집 담당). MCP가 아니다 — 그냥 CLI다. ~/.claude.json에 등록된 적 없다(확인함).
  • “컨테이너 만들려던 것” = po-edit-cell. 그런데 이미 만들어져 있다(581MB, 앱스토어 등록까지 됨). 만든 게 아니라 안 맞춰진 게 남았다.

즉 셋은 한 줄로 이어진다: mcp_phonerec(미니PC·녹화) → Phone T(폰·편집) → po-edit-cell(컨테이너·같은 편집기). 지금 끊긴 곳은 마지막 고리다.

4. 이 작업에서 두 번 갈아엎은 판단 (기록 가치 있음)

① avg_frame_rate 처방이 그대로 버그를 만들었다.
09-22 낮 devlog의 처방은 “r_frame_rate를 쓰라”였다. 그게 컷을 조용히 무시하게 만들었다.
삼성 화면녹화는 VFR — 선언 60/1, 실제 간격 82.73fps. 프레임 N을 N/60초 자리에 놓으면 17.7초 빨라진다.
→ 정정: fps를 두 개로 나눈다. 컷 이어붙일 간격은 avg_frame_rate, 출력 fps는 선언값 + fps=60 필터(타임스탬프 인지).
→ -r 60·-fps_mode cfr 출력 옵션으로는 못 고친다(개수만 센다). setpts=PTS-STARTPTS도 안 된다(동기화는 맞지만 select 구멍을 안 메움).

② “컨테이너와 차이는 베이스 이미지뿐”은 내 주장이지 실측이 아니다.
README와 devlog에 그렇게 썼지만, 컨테이너에 같은 파일을 실제로 돌려 확인한 적이 없다. 그대로 명시돼 있다(README §9, devlog 말미).

③ 내가 낸 결함(기록됨): “100.2초 성공”을 검증 통과로 적었다 → 실제로는 47.48+52.69 = 컷이 안 먹은 값이었다.

5. ★ 지금 어긋나 있는 곳 — 파싱하며 원격을 실제로 재봤다

phone-t/README.md §9는 “컨테이너 안 yt_edit.py는 아직 예전 코드”라고 주장한다. 주장인지 사실인지 확인했다 → 사실이다.

마커 폰(정본) 원격 컨테이너 소스
파일 크기 20,830B 13,277B
LANES 4 0
make_backdrop 2 0
retime 7 0
  • 원격 소스 = 레인 없음 + 블러 한 장 최적화 없음 + VFR 수정 없음. README가 맞다.
  • build-edit-image 마지막 성공: 2026-09-22 04:49 UTC = 13:49 KST.
  • 폰 수정 시각: 09-22 23:13 KST. → 이미지가 폰 수정보다 9시간 앞선다. 즉 컨테이너는 고쳐지기 전 코드로 구워져 있다.
  • GHCR po-edit-cell 풀 토큰: 401(있으나 비공개) — 이미지 존재는 확인됨.

한 줄: 컨테이너는 “안 만들어서”가 아니라 “안 맞춰서” 틀렸다. 소스 3파일 중 1개가 구버전이고, 그 1개가 알맹이다.

6. 안 된 것 / 다음 손 (Boss 지시 대기)

막혀 있는 3개:

  1. 컨테이너 이식 — 폰의 scripts/yt_edit.py를 parksy-image/cell/services/edit/yt_edit.py로 올리고 build-edit-image 재실행.
    - ⚠️ selftest.sh가 이미지 안에서 실제 작업을 돌려 통과해야 GHCR에 올라간다(그래서 검증이 컨테이너 안에서 일어난다).
    - ⚠️ 한글 폰트: python:3.12-slim엔 fontconfig조차 없다. 안 넣으면 폰과 똑같이 조용히 안 그린다.
  2. 한글 제목 — 폰에 한글 폰트가 없어 drawtext가 오류 없이 조용히 안 그린다. 영문만 확인됨.
  3. 컨테이너 이름 변경 — GHCR에 rename 기능이 없다. 새 이름으로 재push 필요. 문자열은 Boss 결정.

그리고 아직 Boss 판단이 필요한 것들:
- phonet을 MCP로 감쌀지 여부 (지금은 CLI. 감싸면 mcp_phonerec와 한 줄로 이어진다)
- 미니PC mcp_phonerec(녹화)는 미완·미검증·미등록 — 살릴지 접을지
- 워크센터 등록 0건 — “만들 수 있게”는 됐는데 “부를 수 있게”가 안 됐다
