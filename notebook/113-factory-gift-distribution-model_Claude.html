2026-09-20 박씨와의 대화에서 확정된 배포 개념 정리. 딥페이크 클라우드 파이프라인(po-deepfake-cloud)을
지인에게 배포하는 방식을 일반화한 것. 이 문서는 “어떻게 선물하는가”의 개념·메커니즘·현재 상태를 기록한다.

1. 핵심 캐치프레이즈

“내가 엔진을 주고, 너는 네 정체성을 꽂아라.”

  • 엔진(생산 시스템) = 컨테이너 + MCP + 파이프라인 = 박씨가 선물하는 것.
  • 정체성(원자재) = 얼굴·목소리·Grok 세션·토큰 = 받는 사람이 자기 것으로 꽂는 것.

2. 이게 기존 배포와 다른 점 — “시스템(공장)을 파는 것”

무엇을 파는가 받는 사람의 지위
APK / PWA 닫힌 소비자 아티팩트(설치만, 수정 불가, 벤더 소유) 소비자로 고정
SaaS (HeyGen·Synthesia 등) 완제품·접근권 소비자·구독자
이 모델 생산 시스템(공장) — 엔진+파이프라인 주인(운영자)
  • 일반 배포 = 완제품(콘텐츠)을 파는 것. 받는 사람은 소비자.
  • 이 모델 = 생산 시스템(공장)을 파는 것. 받는 사람은 자기 정체성을 넣고 자기 산출물을 뽑는 주인.
  • 주체성: 공장이 받는 사람의 계정·시스템·클라우드(GitHub 컨테이너) 안에서 돈다 → 받는 사람이 주인.
  • 편집 가능성: 안이 전부 코드(스크립트·YAML·컨테이너)라 받는 사람이 편집할 수 있다.

3. 시장에서의 위치 — 양극 사이의 빈자리

소유/편집 호스팅 부담
SaaS 벤더 소유, 닫힘 없음(벤더 몫)
셀프호스트(WordPress 등) 내 소유, 편집 가능 높음(내가 설치·운영)
이 모델 내 소유, 편집 가능 없음(GitHub가 대행)
  • “편집 가능성은 셀프호스트 수준인데, 호스팅 부담은 GitHub가 지워버린” 지점이 이 모델의 새 자리.
  • 직접 경쟁자 없음. 부품은 시중에 흩어져 있음(오픈소스 AI 모델 RVC·GPT-SoVITS = “엔진+정체성”의 직계 조상 / AI 아바타 SaaS = 정체성 넣으면 영상 / BYOK·deploy-to-account = 주체성 조각). 그러나 “내 클라우드 계정 + 말 조작 + 정체성 원자재 + 편집 가능 + 컨테이너 선물” 5개를 하나의 상품으로 묶은 것은 못 봤다.
  • 기존 원칙 연결: “도구 = 콘텐츠” (콘텐츠를 만드는 도구·시스템 자체가 상품).

4. 선물 메커니즘 (콜라보가 아니라 템플릿)

  • 콜라보(협업자)는 안 맞음 — 받는 사람을 “내 레포”에 넣는 것 → 내 계정에서 돌고 내 Actions 분을 씀 → 주체성 깨짐.
  • 선물 = 템플릿 레포 + GHCR 컨테이너:
    1. 레포를 GitHub Template로 → 받는 사람 “Use this template” 1클릭 → 자기 계정에 독립 복제본(포크 아님, 자기 것).
    2. 컨테이너는 GHCR에 → public이면 자동 pull, private면 받는 사람 계정에 패키지 읽기 권한만 부여.
    3. 받는 사람이 시크릿 4개 꽂기(얼굴·목소리·Grok 세션·토큰) → 자기 계정에서 자기 분으로 공장 가동.
선물 = 템플릿 1클릭(자기 레포) → GHCR 컨테이너(엔진) → 자기 시크릿 4개(정체성) → 끝
  • 마찰 제거 옵션: 원클릭 부트스트랩 스크립트(curl | bash — 템플릿 생성+시크릿 입력 안내 자동화) 얹으면 “설치”가 사실상 1줄.

5. “편집 가능”의 조건 — 컨테이너와 코드는 같은 것의 두 상태

상태 뭔가 용도
코드(소스) = MCP 스크립트 + 워크플로 YAML + Dockerfile 템플릿 레포에 담김 편집의 대상
이미지(컨테이너) = 그 코드를 빌드한 완제품 GHCR에 있음 그대로 실행
  • 그냥 쓰기(편집 안 함) → 이미지 그대로 pull → 실행. (이미 되어 있음)
  • 편집하기 → 이미지가 아니라 소스를 가져가서 고친 뒤 다시 빌드 → 자기 이미지로.

선물 패키지(템플릿 레포)에 필요한 3요소:
1. 소스 — MCP 코드 + 워크플로 YAML + Dockerfile (편집용).
2. 빌드 워크플로 — 코드 고치면 Dockerfile을 다시 빌드해 자기 GHCR로 push (지금 빠져 있음).
3. 실행 워크플로 — 그 이미지를 돌림 (있음).

6. 현재 상태 / 다음 단계

  • ✅ 실행 워크플로 + 이미지(GHCR po-deepfake-cell:native) — 있음.
  • ⏳ 빌드 워크플로만 템플릿에 추가하면 “가져가서 편집하라”가 완전히 성립. 이것이 마지막 퍼즐.
  • 병행 진행 중(2026-09-20): 미니PC dev_aider 세션이 po-tutorial MCP를 같은 컨테이너에 굽는 작업 진행.
