# 삼성이 좋아할 만한 ADB 자동화 콘텐츠 가이드 — Safe List / No-Go List

> **용도**: 이건 기술 실측 로그가 아니라 **콘텐츠 제작 판단 기준 문서**다.
> `ADB-SAMSUNG-APP-SWEEP-2026-08-22.md`, `ADB-GOODLOCK-CONTROL-2026-08-22.md`,
> `ADB-SHELL-CAPABILITY-CATALOG-2026-08-22.md`, `ADB-SMS-AUTO-VERIFICATION-2026-08-22.md`
> 4개 문서에서 실측한 것들을 "콘텐츠로 공개해도 되는가" 기준으로 다시 분류한다.
>
> **판단 기준**: 마케팅 톤이 아니라 비즈니스 관점 — 삼성 생태계 락인/DevRel에 기여하면
> Safe, 삼성이 파는 보안·결제 신뢰를 훼손하면 No-Go. 마케팅적으로 포장해도 No-Go 항목의
> 성격은 안 바뀐다.

## ✅ Safe List — 콘텐츠화해도 되는 것 (삼성 생태계에 기여)

이유: 삼성은 Good Lock Labs를 통해 서드파티 커스터마이징 개발을 이미 공식 장려 중.
"삼성 기기로 이렇게까지 된다"는 콘텐츠는 타 브랜드 대비 차별화 요소를 무료로 홍보하는 셈.

| 카테고리 | 구체 항목 | 출처 문서 |
|---|---|---|
| 굿락 오케스트레이션 | `am start`로 엣지라이팅+/루틴+/멀티스타 화면 원격 진입 | ADB-GOODLOCK-CONTROL |
| 굿락 즉시 설정변경 | `settings put`으로 엣지라이팅 on/off·두께·알림앱목록 UI 없이 즉시 반영 | ADB-GOODLOCK-CONTROL |
| 생산성앱 원격실행 | 삼성노트/캘린더/연락처/마이파일/갤러리/음성녹음기/카메라 자동 실행 | ADB-SAMSUNG-APP-SWEEP |
| 미디어 캡처 자동화 | `screenrecord`(화면녹화)·`screencap`(스크린샷)·음성녹음기 파일 pull | ADB-SHELL-CAPABILITY-CATALOG |
| 헬스/스마트홈 연동 | 삼성헬스·SmartThings 원격 실행(데이터 조회 없이 화면 진입만) | ADB-SAMSUNG-APP-SWEEP |
| 게임/뮤직 런처 | 게임런처·뮤직 원격 실행 | ADB-SAMSUNG-APP-SWEEP |

**공개 형태 권장**: "삼성 기기 하나로 나만의 자동화 워크플로우 만들기" 류의 파워유저
튜토리얼. 코드/커맨드 전부 공개 가능. Good Lock 커뮤니티(카페/디스코드)나 삼성멤버스에
직접 제출도 검토 가능.

## ❌ No-Go List — 절대 콘텐츠화하지 않는 것

### 1. SMS 기반 2단계인증 자동 우회
- **왜 안 되나**: 프레이밍을 어떻게 잡든 "삼성/카카오 계정 보안 인증을 자동으로 뚫는 법"으로
  읽힌다. 본인 기기+본인 계정이라는 전제는 콘텐츠 소비자 단계에서 사라지고 기법만 남는다 —
  타인 계정 탈취 레시피로 그대로 전용 가능
- **출처 문서**: `ADB-SMS-AUTO-VERIFICATION-2026-08-22.md` — **이 문서는 공개 저장소로도
  옮기지 말고 계속 private `termux-bridge`에만 둔다**

### 2. 삼성월렛(Pay) 자동화
- **왜 안 되나**: 결제앱은 삼성 ToS에 명시적으로 자동화/리버스엔지니어링 금지 조항이 있는
  카테고리. "삼성월렛 자동 실행 성공"이라는 실측 결과 자체를 콘텐츠에 노출하지 않는다
- **출처 문서**: `ADB-SAMSUNG-APP-SWEEP-2026-08-22.md`의 SamsungPay_Wallet 행 — 콘텐츠
  발췌 시 이 행 자체를 표에서 제외할 것

### 3. 시큐어폴더(Secure Folder) 관련 일체
- **왜 안 되나**: Knox TrustZone 격리 보안 기능. "여기는 막혀있더라"는 사실 언급 자체는
  무해하지만, 우회 시도/연구 과정을 콘텐츠화하는 건 절대 금지 — 실제로 시도조차 안 함
  (이미 잠금화면 뜨자마자 중단함, 재시도 없음)

### 4. 통화기록/연락처 등 사생활 데이터 조회 결과 화면
- **왜 안 되나**: 기법(어떤 provider URI를 쓰는지)은 Safe하지만, **실제 조회 결과(전화번호,
  이름 등)를 스크린샷/예시로 노출하면 안 됨** — 콘텐츠 제작 시 반드시 더미 데이터로 재현할 것

### 5. Knox 관련 패키지 전반 (`com.samsung.android.knox.*`)
- 기업 MDM/보안 영역. 자동화 시도/문서화 모두 대상에서 제외 (지금까지도 건드린 적 없음 — 확인차 명시)

## 경계선 케이스 — 판단 필요

| 항목 | 판단 |
|---|---|
| 리마인더 앱 최초권한 자동승인(`pm grant`) | Safe에 가깝지만 "권한요청 팝업 우회"라는 표현이 오해 소지 있음 → 콘텐츠화 시 "권한을 미리 부여해두는 법"으로 순화 표현 |
| 통화기록/연락처 provider 존재 자체를 언급 | 기법만 언급(URI 이름)하는 건 Safe, 실제 조회 데모는 No-Go (위 4번과 동일 원칙) |

## 요약 원칙 3줄

```
1. "삼성 앱을 더 잘 쓰게 도와주는" 콘텐츠 → 공개 OK, 오히려 삼성 생태계에 도움됨
2. "삼성이 파는 보안/결제 신뢰를 깨는" 콘텐츠 → 절대 공개 금지, 내부 문서로만 존재
3. 애매하면 "이 콘텐츠를 삼성 보안팀이 본다면 어떻게 느낄까"로 판정한다
```
